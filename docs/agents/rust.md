# Rust 鲁棒性与运行约束

按外部输入可能非法、网络可能断开、客户端可能取消、推理可能失败的前提实现真实边界。

- **错误处理**：显式处理 `Result`，使用 `?` 或带上下文的错误传播保留来源；
  按错误类型或枚举匹配，不比较错误字符串，不用 `let _ = ...` 静默吞掉失败。
  清理阶段确实无法继续传播的错误也须有明确处置；对外错误不得暴露内部敏感信息。
- **输入与数值**：校验请求体、问题数、候选项数、字段类型、张量 shape / dtype 和索引边界。
  温度必须为有限正数，概率计算须稳定，拒绝非有限输出；限制以方案和实际 bundle 为准，不凭空定值。
- **panic**：请求与推理路径禁止使用 `panic!`、`unwrap()`、`expect()` 处理可失败情况，
  不用 `catch_unwind` 掩盖错误。启动配置或模型加载失败应报告原因并明确退出或保持未就绪，
  不能让客户端非法输入触发进程退出。
- **任务与取消**：异步任务和阻塞推理任务必须有明确的结果接收、退出与资源回收路径；
  不丢弃任务句柄后放任任务运行，不把取消等待误当成底层 CPU 工作已停止。
- **并发与资源**：同步 CPU 推理放在 Tokio 的阻塞执行边界内，共享可变状态使用合适的同步原语，
  不跨 `.await` 持有阻塞锁。连接、文件、permit 和任务均须有明确的释放或结束路径。
- **实际推理生命周期**：并发 permit 必须覆盖真实推理的整个生命周期；HTTP 超时或断开后，
  尚未结束的阻塞推理仍占名额。Session 的共享、可变借用与并行执行遵循所选 `ort` 版本的实际约束。
- **超时与重试**：出站调用有显式超时，覆盖适用的连接、握手和响应阶段；排队有容量与等待时限。
  非幂等操作禁止自动重试，推理重试须计入额外计算和并发开销，不自行添加。
- **可观测性**：使用 Tracing 记录结构化请求结果、耗时和错误，敏感正文不进入日志；
  Prometheus 指标遵循方案，标签保持有界。成功、失败、超时与取消后，queue / inflight 计数须反映真实状态。
- **就绪与退出**：模型、Tokenizer 或 ORT Session 不可用时不得报告就绪或伪造推理成功；
  退出时停止准入，明确处理等待请求与在途推理，不静默丢失工作。
