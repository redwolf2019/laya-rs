# #20 实现评审

基线：`e9bbb22c81579845c9c8ea25951d6bc9aaf3e101`；评审范围为本次工作树。
规格来源为 GitHub #20，平台按用户指令改为仅 Windows 11 x64；测试边界按用户确认的
CLI、HTTP/进程停止、PowerShell 四个动作和发布包执行。两个独立评审代理分别检查
仓库标准和规格，修复后再次静态复核，运行证据见 [验收记录](windows.md)。

## Standards

初次发现两项，均已修复：

- 发布来源使用 workflow 触发 SHA，可能不同于实际 checkout tag；本地构建可能为空。
  `build-windows.ps1` 改为实际 `git rev-parse HEAD`，检查命令失败和格式；无 `.git`
  明确标记 snapshot，另记录源码文件 hash。依据：固定来源和可追溯证据要求。
- readiness 和生命周期等待使用墙上时间，可能受系统时钟调整影响。
  改为 `Stopwatch`。依据：超时使用单调时间的兼容契约。

复核结论：[已验证/HIGH，源码及文档范围] 最新工作树未发现剩余具体标准违规，
也未发现值得单独调整的可能 smells。代理未执行远程测试；不以静态复核代替实测。

## Spec

初次发现三个实现问题和一个测试缺口，代码及测试均已补齐：

- P1：重复 `Start` 的异常清理会停止已有服务。已在清理边界之前拒绝重复启动，
  公开脚本回归要求旧 PID 继续运行且记录不变。
- P2：普通 `Update` 未复用显式外部模型目录。已先校验并复用已提交模型，
  回归候选没有模型归档，要求更新仍成功且模型路径及文件时间不变。
- P2：包内源码 SHA 不一定代表实际构建来源。已按 Standards 中的修复记录。
- 成功更新原来只覆盖同版本，不能证明版本指针切换。新增 A→B 候选，检查
  `current.Version`、`previous.Version`，再更新回 A。

复核结论：[已验证/HIGH，静态范围] 未发现新的具体实现偏差。仍未完成普通用户
四动作和另一用户实际 ACL、干净 Windows 11/VC++/UAC 矩阵，以及公开入口最终资产复验；
这些环境验收缺口见验收记录，#20 保持开放。

两轴统计：Standards 初次 2 项，修复后无剩余实现问题；Spec 初次 3 项实现问题
及 1 项测试缺口，已补齐，正式环境门槛仍未完成。
